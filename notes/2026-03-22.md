# Discrete Critic Stabilization

## Done

- **Refactored `StickyDQN(RainbowDQN)`** — extracted `RainbowDQN` base class (Double DQN, Dueling, PER, multi-step hooks); `StickyDQN` keeps only Markov exploration + switching cost
- **Fixed switching cost bug** — `_bellman_next_q` was reading `data.observations[:, 0]` (current position, dominated by flat → degenerate all-flat policy); corrected to `data.actions` (action at s = position at s'). Validated with switching_cost=0 ablation: both implementations now identical
- **Fixed episode boundary bug** — `_last_action` not reset on exploitation path when `episode_start=True`; fixed with size-guard `_last_action.shape != (n,)` in `predict()`
- **`LambdaReplayBuffer` hook** — `StickyDQN._on_step()` refreshes cache at target update frequency via `isinstance` guard; no extra class hierarchy needed
- **Repository structure** — `src/`, `notebooks/`, `tests/`, `data/`, `archive/` layout for GitHub
- **Optuna Stage 1 gridsearch** — `tests/optuna_hparam_search.ipynb`:
	- Protocol: 1 seed, ASHA (`HyperbandPruner`, rungs 10→30→40), 80 trials, `TPESampler(multivariate=True)`
	- Train: `n_envs=16`, `train_freq=168` (1 week), `episode_len=None`, `gradient_steps=20`
	- Epoch: 13 026 env steps (one training-data equivalent); 40 epochs max per trial
	- Study: `sqlite:///optuna_stage1.db`, `stage1_sticky_dqn_eth`
	- Search space: `learning_rate`, `target_update_interval`, `exploration_fraction`, `mean_hold`, `switching_cost`, `gradient_steps`, `replay_ratio` → derived `batch_size`, `n_steps`, `total_samples` (PER beta annealing)

## Stage 1 Results

Best val return `r ≈ 1.4` (140% net return on 6-month val). Hyperparameter importances:

| # | Param | Importance |
|---|---|---|
| 1 | `exploration_fraction` | 0.26 |
| 2 | `replay_ratio` | 0.20 |
| 3 | `mean_hold` | 0.10 |
| 3 | `total_samples` | 0.10 |
| 5 | `n_steps` | 0.08 |
| 6 | `switching_cost` / `learning_rate` | 0.07 |
| 9 | `gradient_steps` | 0.05 |

Winner profile: high `exploration_fraction` (~0.65), `n_steps=1`, `replay_ratio` ~2–3, low `switching_cost`.
